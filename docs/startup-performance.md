### 实现与数据规模

- 设备本地 IndexedDB 保存搜索与书签视图；原始 Reading 数据仍在 `chrome.storage.local`，书签仍由 Chrome 管理。索引不进入备份、WebDAV 或多设备同步，可从原始数据重建。后台重启和正常重载复用可读索引，不重复搬运整个原生树与镜像。
- Search 和 Book 元数据独立；完整索引先分段准备，再以短事务分批写入，最后按 generation 原子发布。更新期间保留上一代可读数据，旧代按小批次回收。事务之间取消检查仍保留，去掉短写入前后重复的主动等待。
- 大库中出现于大量记录的搜索词不再持久保存冗余 posting。每个版本超过 `max(2048, ceil(count / 5))` 的列表按保守全集处理，最终评分仍核对真实文本，保留匹配总数与排序。架构保持 schema 5，兼容没有省略列表字段的旧快照。
- 广泛查询按最多 256 条的轻量文本/评分块处理，只有可见结果读取完整预览。书签首屏先读取 12 条，翻页、查询与目录按需读取；预览增量修补受影响记录和祖先封面摘要。
- 长时间索引任务运行期间约每 20 秒调用一次轻量 Chrome API，任务结束后释放计时器。该机制修复了纯 CPU/IndexedDB 构建在 MV3 空闲回收前无法完成的问题；它不使后台永久常驻。[Chrome 生命周期说明](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)规定扩展 API 调用会重置空闲计时。
- 交互查询使用前台优先级及约 6 ms 的 Reading CPU 预算，完整构建保持后台优先级。书签或状态变化复用未变的 Reading 模型；标题、项目等变化在检查点取消旧任务。临时结果补入刚保存的 Reading，并按完整 URL 恢复旧书签归属，保留亲手编辑标题和双库来源。
- 小型可见项/偏好消息代替完整镜像回复。手动预览每批最多 12 个原生目标，请求前检查权限、配置、范围、epoch 与完整 URL，空闲提交时再读一次原生树；缓存不参与授予权限。
- 阅读侧栏首屏缓存最多 12 条，保留项目、筛选、自定义顺序与实际数量；先让首屏绘制，再分段归一化完整列表。阅读查询等待为 32 ms，快速切换输入合并为 40 ms。打开文章先激活目标标签页再保存自动状态；保存当前网页在点击时固定标签页 ID。

### 计时含义与覆盖边界

“触发到焦点/结果”从内容脚本的实际显示消息起计；“点击到首卡下一帧”包含入口到导航和文档内帧标记；“搜索”从真实输入到新的匹配列表；“打开”以 Chrome `tabs.onActivated` 到达为主指标。`openPoll` 是驱动后期观察等待，不是页面激活耗时，也不是网页网络加载完成时间。

页面计时器在导航前安装，被动注入暂停的逐次值保留在 `pauseMs`，并早于文档导航起点。DOM 挂载与下一帧分开记录；可见性、焦点、长任务和 RAF gap 保留在原始报告中。晚安装的书签 iframe 计时不用于逐页首帧结论，书签切换采用父侧栏的点击到可见卡片时间。浏览器未提供的 FCP 记录保持缺失，未补成零。

原生测试覆盖真实扩展、Chrome 存储、原生书签、侧栏及标签页接口。测试网页域名在隔离配置中禁止外网解析，打开验证的是保留原始网址的标签页创建/复用与激活。未测实际用户资料、真实 OS Alt/Option+O 加速键、Edge、受保护网页的小窗口唤起或在线网页加载；快速切换采用同一内容脚本的 `QUICK_SWITCHER_SHOW` 路径。不能据此承诺任何资料库、首次升级或所有操作都低于 100 ms。
