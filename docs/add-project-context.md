# 添加时的项目归属提示

本功能从 1.74.5 起提供，更新日期为 2026-11-08。

项目选择框打开时，用同一次现有存储读取判断这批目标网页的归属。显示归属不会保存网页、移动项目或创建项目；确认后才执行操作。

所有目标网页都已在同一可用项目时，直接选中原项目，并把该项目行滚入列表可视区。顶部说明“这 N 篇都已在「项目」”，原项目行标记“全部已在这里”，确认按钮显示“保留在「项目」”。改选其他项目时，按钮及预览立即说明移入操作。

部分已存时，保留“等待整理”的普通初选，并同时呈现三层信息：

1. 顶部显示“待添加 / 已存”数量，下方列出最多三个原项目及数量，更多项目提示剩余项目数。
2. 项目行显示这批网页中“已在这里”的数量；项目原有总数仍单独显示。
3. 确认按钮上方按当前目标显示“新增 / 保留 / 移入”。展开明细可以逐页查看原网址及当前位置。

例如，10 个网页中 4 个待添加、6 个已存，已有网页分属两个项目、各 3 个。选择第一个项目时，预览为“新增4 · 保留3 · 移入3”，按钮为“添加4篇并移入3篇”。此处保留沿用原有保存方式：新网页添加到目标项目，已在目标项目的保留归属，其他已存网页移入目标项目。

## 计数及边界

- 阅读库保存身份继续使用现有 URL 规范化规则，包括跟踪参数、片段和部分 YouTube 链接的处理。实际目标及保存的网址保持原样。
- 多个标签指向同一网页时，新增、已存、保留和移入按唯一网页计数。明细仍保留全部原标签；含已存网页时还说明“标签页数 / 网页数”。保存仍逐标签提取资料，后一个标签可以补齐缺失信息。
- 归档或已删除项目会显示其原有位置，但不成为可选保存目标，也不被算作“已在等待整理”。
- 全部新网页保持现有简单提示及“等待整理”默认。关闭选择框直接保存、显式移动和旧非模态项目浮层继续使用各自原有行为。
- 展示是打开时的快照；确认时保存流程仍读取最新数据，并校验目标项目是否有效。其他页面在此期间修改数据时，最终数量可能随最新状态变化。

## 验证

针对实际后台展示快照、项目 UI 和实际保存循环分别检查了共同项目初选、部分已存、等待整理、归档及缺失项目、重复网址、原网址保留、封面优先级、中英文、搜索、新建、失败重试和键盘输入法兼容。

真实 Chromium 页面使用当前项目 UI 和实际后台函数生成的合成数据，检查了打开即显示归属、切换项目后的数量、逐页明细、键盘确认、取消及窄窗口布局。保存结果通过隔离的 Chrome API 模拟运行实际后台保存循环核验；本轮未操作用户的已安装扩展或个人网页数据。

相关测试：`picker-save-context.test.js`、`picker-add-context.test.js`、`batch-save-unique-stats.test.js`、`save-all-tabs.test.js`。完整回归及浏览器证据记录在同目录的 `add-project-context-validation.json`。
